# Course Library

The library is a git checkout at `${COURSE_LIBRARY:-$HOME/Developer/course-library}` (repo `RobertoVillegas/course-library`, private). Each course folder has a `README.md` (lesson list with one-line overviews and top takeaways) and `lessons/NN-<lesson>.md` with fixed sections: Overview, Outline, Core Concepts, Step-by-step Explanation, Examples / Exercises, Common Pitfalls, Key Takeaways. `catalog.md` rates every course and carries its module guidance; both come from the hand-edited `courses.yaml`.

## Workflow

1. **Sync.** Set `lib="${COURSE_LIBRARY:-$HOME/Developer/course-library}"`. Clone it there if missing (`git clone git@github.com:RobertoVillegas/course-library.git "$lib"`), otherwise `git -C "$lib" pull --ff-only -q`, once per session.
2. **Refresh the semantic index**, when `qmd` is installed. From `$lib`, run `QMD_TRUST_LOCAL_CONFIG=1 qmd update` and then `QMD_TRUST_LOCAL_CONFIG=1 qmd embed`. Only new or changed lessons get embedded, so after a pull this takes seconds. Every qmd command in this skill carries `QMD_TRUST_LOCAL_CONFIG=1`: without it qmd silently swaps the library's multilingual embed model for its default one. If `.qmd/index.sqlite` does not exist yet, the first embed takes about 45 minutes. Start it in the background, tell the user, and search with `search.py` until it finishes.
3. **Read the catalog.** Run `python3 "$lib/search.py" --list` to see each course's lessons, language, status, and rating. Read the course's section in `catalog.md` before leaning on it.
4. **Search.**
   - From `$lib`, run `QMD_TRUST_LOCAL_CONFIG=1 qmd query "<question>" --no-rerank -n 8`.
   - Write the question in the language of the courses (the `--list` language column), translating the user's question when needed. If the catalog mixes languages, run the query once per language.
   - Drop `--no-rerank` when the top results look off: reranking is slower (~18 s) and more precise.
   - Use `python3 "$lib/search.py" "<words>"` (BM25, `--course <text>`, `--limit N`, `--raw` for FTS5 syntax) for exact terms, or whenever qmd is unavailable.
   - Results are done when they cover the question from more than one angle, or retries with synonyms and the course's own vocabulary turn up nothing new.
5. **Weigh** each hit before using it:
   - Apply the course's module guidance (in `catalog.md` and `courses.yaml`) by matching the rule text against the lesson title. When several rules match, the longest match wins.
   - Lead with `preferred` and `active` material. Use `reference` material for detail. When citing `superseded` or `deprecated` material, say what replaces it.
   - When courses disagree, favour the higher rating and the more recent `years`.
   - For courses with `aging: fast` (AI tools, no-code UIs), state the content dates, since steps tied to a tool version may have changed.
6. **Read and answer.** Read the course `README.md` for orientation, then only the lesson files the answer needs. Answer from the notes and cite the lesson path for each claim. The notes are generated summaries of videos and documents. Where a passage is marked "unclear", the source was ambiguous: say so and leave the gap open.

## Rules

- The library is read-only here. syllabus regenerates the lessons on devbox-gpu, and the user curates `courses.yaml` (ratings, status, guidance). After changing `courses.yaml`, run `syllabus catalog --library-dir "$lib"` from the syllabus repo to rebuild the catalog.
- Quote or link library material where it is needed instead of copying it into other repos or skills.
